ODE Solver for Spring-Damper System (Harmonic Oscillator) 2023-03-31

과제 요약

1차원 스프링–댐퍼(조화 진동자) 운동을 수치 적분으로 시뮬레이션. 여러 ODE 솔버를 구현해 비교. 천장에 고정된 스프링 끝에 질량이 매달린 구조, y축만 사용.

운동 방정식

a = −(Ks/m)(x − Lrest) − (Kd/m)v + g

훅 법칙(스프링력) + 선형 댐핑 + 중력. 2차 ODE: mẍ = −Ks(x − L0) − Kdẋ + mg

구현한 ODE 솔버

Explicit Euler

vn+1 = vn + dt·an,   xn+1 = xn + dt·vn

위치 갱신에 이전 속도 사용. dt가 크면 불안정(에너지 발산).

Symplectic Euler

vn+1 = vn + dt·an,   xn+1 = xn + dt·vn+1

위치 갱신에 새 속도 사용. 에너지 보존 특성이 Explicit보다 좋음.

Implicit Euler

∂f/∂v, ∂f/∂x로 1차 선형화해 Δv를 구한 뒤 갱신. 큰 dt에서도 안정적. 에너지는 감쇠.

파라미터

Ks↑ → 진동 주기↓. Kd↑ → 과감쇠. Time Step↑ → Explicit만 불안정, Symplectic/Implicit는 안정.

UI

ImGui: Gravity, Ks, Kd, Mass, Time Step, Rest 길이, ODE Solver 선택, Restart.

실험

dt를 키우며 솔버별 동작 비교. Explicit 발산, Symplectic/Implicit 안정을 영상에서 시연.

Tech: C++, OpenGL, ImGui

Bead on the Wire (Constraint Force) 2023-04-12

과제 요약

입자를 직교좌표 p=(x,y)로 두고, 원점 중심 단위원 위에만 움직이도록 구속. Lagrange multiplier(λ)로 구속력을 계산해 시뮬레이션.

1. 구속 조건

단위원: C(p) = ½(x² + y² − 1) = 0
구속의 기울기: ∇C = p (원점→입자 방향)

2. 적용 힘 (Applied force)

gravity_force = (0, m * g);
damping_force = -k * velocity;
applied_force = gravity_force + damping_force + mouse_force;

중력 (0, mg), g=−9.8, m=1. 댐핑 −kv는 참고 구현용(무시 가능). 마우스 외력은 아래 4번에서 설정.

3. Lagrange multiplier λ

λ = (−F·p − mv·v) / (p·p)

lambda -= feedback_alpha * (dot(p,p) - 1) / 2;  // 위치 보정
lambda -= feedback_beta * dot(p, v);             // 속도 보정

Baumgarte 안정화로 수치 오차로 원에서 벗어나는 걸 줄임.

4. 구속력과 가속도

constrained_force = lambda * position;
acceleration = (applied_force + constrained_force) / mass;

구속력 = λp, a = (F_applied + λp) / m

5. 마우스 외력 (UI)

deltaPos = current_pos - prev_mouse_pos;
mouse_force = scale * vec3(deltaPos.x, -deltaPos.y, 0);

마우스 이동량에 비례. y는 화면 좌표라 −deltaPos.y로 위로 드래그 = 위쪽 힘.

6. 수치 적분 (Symplectic Euler)

next_velocity = velocity + dt * acceleration;
next_position = position + dt * next_velocity;

vn+1 = vn + Δt·an, pn+1 = pn + Δt·vn+1. 속도 먼저 갱신 후 새 속도로 위치 갱신.

7. 초기 조건·상수

mass = 1.f;
position = (0, 1, 0);
velocity = (0, 0, 0);

m=1 kg, p(0)=(0,1), v(0)=(0,0), g=−9.8 (과제 명세)

Tech: C++, OpenGL, ImGui

Collision Detection between Spheres 2023-04-28

과제 개요

3D 공간에 서로 다른 반지름을 가진 N개의 구가 랜덤 위치에 있다.

  1. Broad Phase Collision Culling : 각 구를 감싸는 AABB를 두고, Sweep and Prune으로 겹칠 가능성이 있는 구 쌍을 찾는다.
  2. Narrow Phase Collision Detection : 실제로 겹치는 구 쌍을 찾고, 그 쌍에 대해 침투 깊이(penetration depth)를 계산한다.
  3. 렌더링 : (a) 잠재적 충돌 구, (b) 실제 충돌 구, (c) 침투 깊이 벡터를 OpenGL로 그린다. 침투 깊이 벡터: 가장 깊이 침투한 점에서 시작해, 크기는 침투 깊이인 벡터.
  4. UI : 구 개수 변경, 구마다 다른 색, flat shading 또는 텍스처로 구의 방향 표현, 구 재생성·충돌·침투 깊이 재계산.

1) Broad Phase: AABB + Sweep and Prune

과제 요구 : 각 구를 감싸는 AABB를 두고, Sweep and Prune으로 잠재적으로 겹치는 구 쌍을 찾는다.

AABB

  • 각 구(Sphere)는 m_AABB를 가짐 (sphere.h)
  • AABB는 m_start_position, m_end_position (축 정렬 박스의 두 꼭짓점) (AABB.h)
  • 구 생성 시: m_AABB = AABB::Create(m_center - vec3(r,r,r), m_center + vec3(r,r,r)) (sphere.cpp Init)

Sweep and Prune

  • Context::SweepAndPrune() (context.cpp 324행~)
  • x, y, z축마다: 각 구의 AABB start/end 좌표를 이벤트로 등록 CompareHelper(sphere, sphere->GetAABB()->m_start_position.x, true), CompareHelper(sphere, sphere->GetAABB()->m_end_position.x, false) (x축 예시). CompareHelper::compare로 값 기준 정렬 후 FindCollidingSpheres(helpers, x_colliding_spheres)로 해당 축에서 겹칠 수 있는 쌍 구함
  • 세 축 결과의 교집합: temp_output = Intersection(x, y), m_broad_colliding_spheres = Intersection(temp_output, z) (373–374행)
  • 결과: AABB가 겹치는 구 쌍 m_broad_colliding_spheres

FindCollidingSpheres (416행~): 정렬된 이벤트를 순회하며, m_is_start일 때 현재 "열린" 구들과 모두 쌍을 만들어 넣고 리스트에 추가, m_is_start == false일 때 해당 구를 리스트에서 제거.

2) Narrow Phase: 실제 충돌 쌍 + 침투 깊이

과제 요구 — 실제로 겹치는 구 쌍을 찾고, 그 쌍에 대해 침투 깊이를 계산한다.

실제 겹침 판별

  • FindActuallyOverlappedSpheres() (context.cpp 384행~). Broad 결과 m_broad_colliding_spheres만 순회
  • distance = glm::distance(center1, center2), radius_sum = r1 + r2
  • 충돌 조건: distance < radius_sum (401행). 충돌한 쌍은 m_narrow_colliding_spheres에 넣음

침투 깊이 벡터

  • 과제: "가장 깊이 침투한 점에서 시작하고, 크기는 침투 깊이"인 벡터
  • ray = normalize(center2 - center1)
  • 구1 표면(구2 쪽): penetrated_point1 = center1 + radius1 * ray
  • 구2 표면(구1 쪽): penetrated_point2 = center2 - radius2 * ray
  • 두 점을 잇는 선분 = 침투 깊이 벡터 (방향 p1→p2, 크기 = radius_sum - distance)
  • m_lines.push_back(Line::Create(penetrated_point1, penetrated_point2)) (409행)
  • Log에서 침투 깊이: e.first->GetRadius() + e.second->GetRadius() - glm::distance(...) (148행)

3) 렌더링 (a)(b)(c)

과제 요구 — (a) 잠재적 충돌 구, (b) 실제 충돌 구, (c) 침투 깊이 벡터를 OpenGL로 그린다.

View 모드

  • Model View (VIEW_MODEL): 구만 그리며, 각 구는 자신의 색 m_color (sphere.cpp Render)
  • Broad view (VIEW_BROAD): ComputeCollision() → SweepAndPrune() 후, m_broad_colliding_spheres에 포함된 구만 SetIntersected(true). 렌더 시 m_isIntersected면 빨강, 아니면 초록 → (a) 잠재적 충돌 구 시각화
  • Narrow view (VIEW_NARROW): FindActuallyOverlappedSpheres() 후, m_narrow_colliding_spheres에 포함된 구만 SetIntersected(true) → (b) 실제 충돌 구 시각화
  • Penetration view (VIEW_PENETRATION): m_narrow_colliding_spheres로 충돌 쌍·침투점 계산 후, 침투점 두 개를 잇는 선만 m_line_program으로 그림 (m_lines, line->Render) (context.cpp 212–226행) → (c) 침투 깊이 벡터 시각화

색 구분 — Model View: Sphere::Init()에서 구마다 m_color 랜덤. Broad/Narrow: 충돌 참여 여부에 따라 빨강/초록.

Rigid Body Dynamics: Part 1 Colliding Contact 2023-05-12

과제 요구사항 요약

  • 3D 공간에 N개의 구(solid sphere)와 무한 질량의 평면(plane)이 있다. 구는 랜덤 반지름, 질량 M.
  • 반발계수(coefficient of restitution)는 탄성에 가깝게 (예: e = 0.9).
  • 구의 관성 텐서는 Wikipedia 등 참고 (solid sphere: I = (2/5)MR²).
  • 고정 타임스텝(fixed time-stepping)과 임펄스 기반 동역학(impulse-based dynamics)으로 충돌 접촉(colliding contact)을 시뮬레이션.
  • Part 1 Colliding Contact 결과 활용: 구–구 충돌 검사. 추가로 구–평면 충돌 검사.
  • 접촉 시각(time of contact)을 구하지 않음 → 침투 상태(penetration)에서 임펄스를 적용.
  • Baraff 강의 노트(notesg.pdf)의 pseudo code, Geometric Tools의 RigidBody 등 참고 가능.
  • 렌더링: texture mapping 또는 flat shading으로 회전 운동이 잘 보이게. 소스코드, 실행파일, readme 제출.

1. 데이터 구조: Rigid Body, Sphere, Plane

RigidBody (rigidbody.h)

  • 선운동: m_velocity, m_momentum, m_mass
  • 각운동: m_angular_vel, m_angular_momentum, m_inertia (스칼라 관성)
  • 반발계수: m_coefficient_of_restitution (기본값 0.9)
  • 회전 표현: m_quaternion (향후 확장용)

Sphere (sphere.h, sphere.cpp) — RigidBody 상속

  • 중심 m_center, 반지름 m_radius, AABB(충돌 검사용)
  • Init: 중심·반지름·색 랜덤. 반지름 getRandomFloat(0.5f, 1.0f)
  • 질량: m_mass = m_radius * getRandomFloat(0.8f, 1.2f)
  • 관성: m_inertia = 0.4f * m_mass * m_radius * m_radius → Solid sphere I = (2/5)MR²이므로 0.4 = 2/5 사용
  • 초기 속도·각속도 랜덤 또는 0. m_momentum = m_mass * m_velocity, m_angular_momentum = m_inertia * m_angular_vel

Plane (plane.h) — RigidBody 상속

  • 무한 질량. 속도/질량 미사용, 경계만 사용
  • m_x, m_z: 평면이 유한 사각형으로 취급되는 범위 (구가 |x| ≤ m_x, |z| ≤ m_z 안에 있을 때만 구–평면 충돌 처리)

2. 충돌 검사

구–평면 (context.cpp Update, 84–86행)

  • is_close: 구 중심이 바닥에 가깝다 → sphere->GetCenter().y - sphere->GetRadius() < epsilon (epsilon = 0.01), 그리고 |center.x| ≤ m_x, |center.z| ≤ m_z
  • 접근 중: v_rel = dot(velocity, (0,1,0)) < 0 (아래로 내려가는 속도 성분)
  • 접촉 시각을 구하지 않음 → 이미 침투한 상태(또는 epsilon 이내)에서 위 조건이면 그 프레임에서 임펄스 적용

구–구

  • Part 1 Colliding Contact 결과 재사용: SweepAndPrune() → FindActuallyOverlappedSpheres()
  • m_broad_colliding_spheres, m_narrow_colliding_spheres로 실제 겹치는 구 쌍만 취급 (distance < r₁ + r₂)

3. Colliding Contact — 임펄스 적용

구–평면 (context.cpp 80–104행)

  • 접촉점: 바닥 위 점 pa = (center.x, 0, center.z)
  • 접촉점에서의 속도: padot = velocity + cross(angular_vel, pa - center)
  • 법선: n = (0, 1, 0). 상대 접근 속도: vrel = dot(n, padot)
  • 임펄스 크기 j: 단일 강체–무한 질량 벽 공식. ra = pa - center
  • 적용: m_momentum += j*n, m_velocity = m_momentum/m_mass, m_angular_momentum += cross(ra, j*n), m_angular_vel 재계산

구–구 (context.cpp 107–168행)

  • 접촉점: p1 = center1 + r1 * normalize(center2 - center1), p2 대칭
  • 접촉점 속도: p1dot = v1 + ω1×(p1-center1), p2dot = v2 + ω2×(p2-center2)
  • 법선: n1 = normalize(center1 - center2), n2 = -n1
  • 상대 접근 속도: vrel = dot(n1, p1dot - p2dot). vrel < 0일 때만 임펄스 적용
  • 임펄스 크기 j: 두 강체 공식 (분모에 1/m1 + 1/m2와 각 구의 관성 항 포함). j = -(1+e)*vrel / (분모)
  • s1: m_momentum += j*n1, m_angular_momentum += cross(ra1, j*n1). s2: n2, ra2로 동일 적용

4. 고정 타임스텝 적분 (move)

  • 힘 적용 (171–178행): 구가 바닥에 가깝고 붙어 있을 때(isClose)는 force = 0 (추가 침투 방지). 그 외 gravity = (0, m_gravity * m_mass, 0) (m_gravity = -9.8)
  • Sphere::move(force, timestep) (sphere.cpp 113–119행): m_momentum += timestep * force, m_velocity = m_momentum / m_mass, m_center += timestep * m_velocity, 각속도·쿼터니언 갱신
  • Fixed time-stepping: 매 프레임 동일한 m_timestep(0.01)으로 충돌 처리 후 한 번씩 move 호출

5. 렌더링

구·평면은 lighting 셰이더와 메쉬로 그린다. Texture mapping 또는 flat shading으로 구의 방향/회전이 보이도록 구현 (메쉬+라이트 기반 렌더링).

Rigid Body Dynamics: Part 2 Resting Contact 2023-05-26

과제 개요

Part 1 에 Resting Contact를 추가한 강체 동역학. 구가 바닥·구끼리 "붙어 있을 때"도 중력을 끄지 않고, 매 프레임 velocity impulse로 접촉점 법선 속도를 상쇄해 침투를 줄이려는 구현.

구현 내용

  • 1) Colliding contact (context.cpp 79–166행)
    Part 1 과 동일. 구–바닥: is_close이고 v_rel < -v_epsilon일 때 접촉점 속도 padot = v + ω×r, 법선 n=(0,1,0), j = -(1+e)*vrel / (1/m + 관성항) 적용. 구–구: FindActuallyOverlappedSpheres()로 충돌 쌍 구한 뒤, vrel < -v_epsilon일 때만 (1+e) 포함한 임펄스로 반발.
  • 2) Resting contact (168–264행)
    추가한 부분. 구–바닥: is_close이고 |v_rel| < v_epsilon일 때 j = -vrel / (1/m + 관성항) (반발계수 없음). 구–구: m_narrow_colliding_spheres 쌍에 대해 |vrel| < v_epsilon일 때 같은 식으로 j = -vrel / (분모) 적용. 접촉점에서 남은 법선 속도를 impulse로 상쇄하는 의도.
  • 3) Move (266–272행)
    모든 구에 항상 중력 적용: sphere->m_force = gravity, sphere->move(m_timestep). 바닥에 붙어 있어도 force를 0으로 두지 않음.
  • 상수: distance_epsilon = 0.01 (접촉 판정 거리), v_epsilon = 0.6 (colliding: v_rel < -v_epsilon만 반발, resting: |v_rel| < v_epsilon일 때 지지 임펄스).

Part 1 과의 차이

구분 Part 1 Part 2
Colliding (튕김) 구–바닥·구–구, 접근 시 (1+e) 임펄스 동일. v_rel < -v_epsilon일 때만 적용
Resting (붙어 있을 때) 없음 추가. |v_rel| < v_epsilon일 때 j = -vrel/… 로 법선 속도 상쇄
Move 시 중력 바닥에 가까우면 force = 0 항상 m_force = gravity, 중력 유지

구현의 범위와 한계

Resting contact는 "접촉점에 남은 법선 속도(normal velocity)를 매 프레임 velocity impulse(j = −v_rel / …)로 상쇄한다"는 식으로 설계했고, 그에 맞춰 구–바닥·구–구 모두 적용해 두었다. 반대로, 쉬고 있을 때도 침투가 누적되면 접촉점에 작은 법선 속도가 남아 있다는 뜻이므로, 이걸 더 강하게 상쇄하거나 위치 보정을 넣는 쪽이 다음 단계가 된다.

Impulse만으로는 평면 침투를 완전히 막기 어렵다는 점은 강체 동역학 쪽에서도 흔히 다루는 이슈이고, LCP·stabilization(위치/속도 보정)을 도입하면 더 안정적인 resting이 가능하다. 이번 구현은 "고정 타임스텝 + impulse 기반" 범위 안에서 resting contact를 넣어 본 것이고, 한계를 인지한 상태에서 stabilization은 별도 단계로 두었다.
